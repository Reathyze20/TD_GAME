# Balance sweep — S2 × S3 outcomes, M1 diagnosis

Generated by `scripts/_balance_sweep.gd` via S2's `LevelSimulator`. Every simulated
cell uses the SAME seed (20260829), so a column-to-column comparison at a fixed level
is fair; do NOT compare seeds against each other, since none are varied here.

`wave` is the wave index reached at the time the run ended — win, loss, or TIMEOUT
(the run did not resolve within 10800 simulated frames / 180 simulated seconds,
itself a reportable result, not a harness failure).

**Sections 3–5 are static** — computed from `data/` and `Game`'s constants with no
simulation — so they stay meaningful for a level no strategy can finish.
## 0. Where the run breaks (static verdict)

Arithmetic only — no simulation, no strategy. `must prevent` is the Focus damage the
player has to stop for the run to end above zero: `total leak − (pool − 1)`. `usable
spots` counts build blocks a fresh board actually allows: with `routine_gates` on
that is the blocks inside `CORE_ROUTINE_RADIUS`, since `in_routine` gates a habit's
FIRING and not merely its placement. `opening buy` is how many of the cheapest
non-chip habit `start_dopamine` affords, against how many spots there are to fill.

## 5. Wave composition vs the Focus budget (static)

the worst case, and the ceiling the player is defending against. `% of pool` is that
against the level's whole `LevelData.focus`. Anything at or over 100% means one
un-defended wave ends the run on its own.
